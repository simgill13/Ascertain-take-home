# Agent team

This repository is set up so a coding agent in Cursor, Claude Code, or Codex can build, review, and verify the dashboard against the original task in `docs/ASSIGNMENT.md`.

## Where things live

| Concern | Canonical file | Cursor | Claude Code | Codex |
| --- | --- | --- | --- | --- |
| Instructions | `AGENTS.md`, `backend/AGENTS.md`, `frontend/AGENTS.md` | reads `AGENTS.md` and `.cursor/rules/*.mdc` | reads `CLAUDE.md`, which imports `AGENTS.md` | reads `AGENTS.md` |
| Skills | `.agents/skills/<name>/SKILL.md` | `.cursor/skills` symlink | `.claude/skills` symlink | native |
| Subagents | `.claude/agents/<name>.md` | reads `.claude/agents` natively | native | `.codex/agents/<name>.toml`, generated by `scripts/sync_codex_agents.py` |

Regenerate the Codex files after editing an agent:

```bash
python3 scripts/sync_codex_agents.py
```

## Roles

Builders edit files inside their ownership boundary.

| Agent | Owns |
| --- | --- |
| `database-engineer` | `backend/app/models`, `backend/alembic`, `backend/app/seed`, `docs/DATA_MODEL.md` |
| `backend-engineer` | `backend/app` except models and seed, `backend/tests` |
| `frontend-engineer` | `frontend/` |
| `ci-engineer` | `.github/`, `scripts/verify.sh`, `scripts/export_openapi.py`, `backend/openapi.json`, `docs/CI.md` |

Reviewers are read-only and return findings.

| Agent | Checks |
| --- | --- |
| `qa-engineer` | lint, types, pytest, Vitest, Playwright, suite timings, flaky tests |
| `design-reviewer` | responsive layout, WCAG 2.2 AA, reduced motion, landing chunk isolation |
| `product-reviewer` | the journeys in `product-walkthrough` |
| `readability-reviewer` | the checklist in `review-readability` |
| `spec-compliance-reviewer` | every requirement in `docs/ASSIGNMENT.md` with evidence |
| `scalability-engineer` | capacity to 100k to 1M users; specifies fixes that builders implement (`docs/SCALABILITY.md`) |

The master agent is whichever agent the developer is chatting with. It follows `orchestrate-feature`.

## Project skills

`orchestrate-feature`, `spec-compliance-check`, `verify-all`, `review-readability`, `review-design-accessibility`, `product-walkthrough`, `landing-page-motion`, `ci-pipeline`, `scale-review`.

## Vendored design skills

Installed with `npx skills add <repo> --skill <name> --copy` into `.agents/skills/`. Hashes are in `skills-lock.json`. Reviewed on install: each is a single flat skill folder, none runs scripts, and `web-design-guidelines` fetches its rule list from GitHub at review time, so it needs network access.

| Skill | Source | Commit | License | Used by | Notes |
| --- | --- | --- | --- | --- | --- |
| `frontend-design` | anthropics/skills | 683bc88e56f3 | Apache-2.0 | frontend-engineer | Two-pass brief: tokens then build |
| `design-taste-frontend` | Leonxlnx/taste-skill | e3c92037548e | MIT | frontend-engineer | Large (about 1,200 lines). Mentions GSAP; this project uses `motion/react` only |
| `web-design-guidelines` | vercel-labs/agent-skills | 063bee94c3f4 | no license file in repo | design-reviewer | Fetches rules from vercel-labs/web-interface-guidelines |
| `apple-design` | emilkowalski/skills | e8a175de22ae | MIT | both | Spring motion, reduced motion, restraint |
| `animation-vocabulary` | emilkowalski/skills | e8a175de22ae | MIT | both | Shared names for motion effects |
| `hallmark` | nutlope/hallmark | 13ac0ec7e148 | MIT | design-reviewer | Second-pass anti-slop audit; includes a `references/` folder |

Project skills override vendored skills when they conflict. `review-design-accessibility` and the motion rules in `.cursor/rules/frontend-react.mdc` always win.
